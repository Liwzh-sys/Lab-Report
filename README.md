# 幂等键的语义漂移

> 一次 AI 工具调用的重试，凭什么算"同一次"？

**仓库地址：<https://github.com/Liwzh-sys/Lab-Report>**

课程第七讲 课时3 的兵器墙上写着：**"键由应用生成，不让模型自己起。"**

这句话对了一半。它规定了键的**作者**，没规定键的**内容**，更没说"两次调用是不是同一次"该由谁判定。本项目用一组可复现实验回答后半个问题，并且如实交代这组实验能证明什么、不能证明什么。

**当前是 v4（第四轮收尾后）。** v1 的三个大主张已撤回；v2 的四处结构性缺陷（事件分类、episode 计数、语义标签、替代判据）已在 v3 改掉；v3 遗留的**主指标口径**问题（保义重复与真实变义混在一个数里）已在 v4 改完。逐条质疑的处置理由与改前改后数字见 [`docs/response.md`](docs/response.md)（第一、二轮）、[`docs/response3.md`](docs/response3.md)（第三轮）、[`docs/response4.md`](docs/response4.md)（第四轮收尾），完整报告见 [`docs/report.md`](docs/report.md)。

## 结论（收窄版）

在当前**手工构造**的工具集与扰动集上，字段归一化和槽位抽取确实降低了设定目标函数里的保义重复代价；逐条规则审计也揭示了有损转换的风险。但**标签和成本依赖手工契约与设定**（不是独立标注、也不是实测运行数据），测试覆盖有限，现有结果**不能证明任何策略具有通用安全性**。

同一批 30 个逻辑操作 / 6 个工具 / 8 组种子 / 113 对同工具诱饵：

| 策略              | 重复代价 `dup`       | 漏做代价 `miss` | 错合并率 `fp`（分母 113） | 跨工具碰撞 `ns`（分母 5） | episode 分裂率 `fn`（诊断量，分母 30） |
| --------------- | ---------------- | ----------- | ----------------- | ---------------- | --------------------------- |
| 裸参数序列化基线        | 35.375 ± 4.03    | 3.10        | 0.000             | **1.000**        | 0.988                       |
| 仅 SAFE 归一化      | 7.625 ± 1.77     | 0.00        | 0.000             | 0.000            | 0.408                       |
| SAFE + 全部 RISKY | **1.875 ± 1.36** | **19.20**   | **0.416**         | 0.000            | 0.288                       |
| **槽位投影（含守卫替代）** | **3.750 ± 1.16** | 0.00        | 0.000             | 0.000            | 0.329                       |
| 槽位投影（不含替代）      | 7.625 ± 1.77     | 0.00        | 0.000             | 0.000            | 0.408                       |

`±` 是 8 个种子的**样本标准差（ddof=1）**，不是置信区间；这 8 个种子共享同一组诱饵，**不是 8 个独立样本**。

**`dup` 的定义在 v4 改过一次，这一列与前几版不可直接对比。** 旧口径 `dup = Σ(键数−1)×c_dup` 把"该复用却拆开"（损失）和"该拒绝而拆开"（做对了）算进同一个数；新口径只数前者。因此数字会变小，**变小不是策略变好，是分母里剔掉了不该算的部分**。旧口径保留为 `dup_cost_legacy`，只与历史数值对表用。

**两边都想要的写法是不成立的**：同一条行为不可能同时是"冲突已被正确拒绝"和"多执行了一次"。选择哪一边，就要放弃另一边对应的那个数。论证见 `docs/response4.md`。

四条必须与数字一起读的限制：

1. **参数类策略在"独立新意图"上 100% 错合并。** 30 对事件参数完全相同、身份不同，任何只看参数的键都分不开（`fig5`）。这是**原理性上界**，不是实现缺陷。
2. **RISKY 全开的 `dup` 最低，是假象。** 它的 `fp = 0.416`、`miss = 19.20`，代价被搬到了漏做侧。`dup` 和 `miss` 不能相加成一个"总代价"当作单一排序依据。
3. **五条 RISKY 规则里没有一条是纯收益**，最好的（剥离断言强度）净代价也是 +0.65。而且 32 个子集里，**没有一条多开规则的组合比单开更好**——前沿只剩 4 个点、3 组坐标，其中 `strip_intensity+text_bag` 与单开 `strip_intensity` 坐标完全相同。
4. **顺序依赖真实存在**：五条全开正序 21.08 / 反序 19.23，Δ = −1.850；三规则组合最大 Δ = −2.400。规则集合不是无序集合。

## 方法要点

### 把键看成聚类器

一次工具调用要在两类错误之间选边：

- **漏合并**（该并没并）→ 重复执行，代价 `c_dup`
- **错合并**（不该并却并了）→ 该做的没做，代价 `c_miss`

两者不对称，所以**不存在"最优的键"，只存在"按代价标定过的键"**。

### 四类事件，第四类是原理性上界

v2 把"保义改写"和"真实变义"压成一类，于是 53 次成功合并被记成了 53 次冲突。v3 按两个独立维度切开，共 **176 对**：

| 事件类型                 | 身份     | 语义     | 该怎么处理      | 对数  |
| -------------------- | ------ | ------ | ---------- | --- |
| `replay` 原样重放        | 同一个    | 未变     | 复用         | 30  |
| `replan_equiv` 保义改写  | 同一个    | **未变** | 复用（契约背书）   | 53  |
| `replan_change` 真实变义 | 同一个    | **已变** | 拒绝并报冲突     | 63  |
| `new_intent` 独立新意图   | **新的** | 可以是任意  | **必须执行两次** | 30  |

**四类事件映射到三种动作**，其中 `reuse` 覆盖两类 ⇒ **动作不能反推事件类型**。`contract_check.py` 第 [8] 组断言这一条。

第四类有 30 对参数完全相同、身份不同。参数形态相同却标签相反，这就证明**任何只看参数的键都有不可消除的错误**。

### 语义契约：判定标准必须独立于实验

v1 的问题不是算错了，是**标准散在三个地方且互相矛盾**：扰动器说 `2026-08-01` 是 `2026-08` 的同义写法，报告说月精度与日精度不可合并，诱饵集又拿它当变义反例。

现在收敛成唯一真相源 `src/contract.py`：生成侧（`perturb`）与判定侧（`policy`/`structured`）都从它读，`contract_equiv()` 是标签核对的唯一基准（不用 key 函数自证），`contract_check.py` 验证两侧一致。核心声明：

| #   | 声明         | 内容                                                       |
| --- | ---------- | -------------------------------------------------------- |
| 1   | 时间精度       | `2026-08-01` 与 `2026-08` 是**不同操作**；`MONTH_EQUIV` 只放同精度别名 |
| 2   | 缺年份        | 裸"8月" → `??-08`，**不猜**年份                                 |
| 3   | 字段契约       | 6 个工具逐一列 `key_fields` + `why`；`IGNORABLE_FIELDS` 全空且显式声明 |
| 4   | 类型转换       | `TYPE_COERCIBLE` 白名单；`note`/`subject` 永不在内               |
| 5   | 别名         | `ALIAS_FIELDS` 白名单；站号别名只对 `station` 开放                   |
| 6   | 替代判据       | **逐段归属**：每段都必须有解释，否则整字段保留原文（不是"残余为空"）                    |
| 7   | 命名空间       | 键 = `tool + "\|" + 字段字典`                                 |
| 8   | 诱饵最小性      | 同工具诱饵必须只改 1 个字段，由 `Decoy.__post_init__` 强制               |
| 9   | 事件四类       | 身份标签不可由参数差异推出                                            |
| 10  | **沉默不是许可** | 不在白名单上的一律原样保留                                            |
| 11  | 空白可折叠性     | 按字段声明，**默认不折叠**；`note` 逐字保留                              |
| 12  | 未知字段       | 显式策略 `reject`/`ignore`/`keep`，本项目选 `reject`，`__` 前缀豁免    |

**这些仍然是我写的，而且这一轮撞到了它的反例。** 隐藏集首跑 6/8，失败的 `正-站号大小写` 与 `正-作业名换分隔符` 根因是 `norm_station` 的字符类写 `[SB]`、`STATION_PAT` 也是 `[sbSB]`——主集只有 S07/S12/S31/B04，于是**站号词表与主集取值耦合**。整个项目围绕这份契约自洽，正好把这处掩盖了。

所以不说"标准已经统一"。内部一致不等于对外正确。

### 重复代价只有一个实现

`evaluate.dup_units()` 是**全项目唯一**算重复代价的地方，返回三个量：

```python
{"equiv_unit": float,    # 只有"期望复用却另起新键"才计 → 主指标 dup 的单位量
 "legacy_unit": float,   # 全部额外键，旧口径，只为对表
 "extra_keys": float}    # Σ(键数−1)，诊断量，名为 split_score
```

第三版里这个量在**三个地方**各写了一遍（E3 粗扫、E3 细扫、E7 审计），三处都手算 `len(keys)-1`。改一处漏两处是必然的，而漏掉的那处会悄悄给出与主表矛盾的数。现在 E3 粗扫、E3 细扫、E7 `_audit`、E7 `run_order`、主表**全部调用同一个函数**。

判定逻辑只有一句要紧的：**看到一个样本另起了新键，先去读它的 `expected_action`**。期望是 `reuse` 才是损失；期望是 `reject`/`execute` 说明这个键本来就该分开，那是策略执行正确。只看键数永远分不出这两种情况。

### λ，不是 ρ

`λ` 是**重复代价的整体缩放量，只作用于 `c_dup` 一侧**，`c_miss` 不动。所以 `λ=1` 不等于"所有工具 `c_dup=c_miss`"。λ=1 时各工具真实代价比是：`submit_batch_job` 2.50 / `write_qc_note` 1.25 / `send_email` 2.00。

v1 写的"ρ≈2 是相变点"是**网格分辨率造出来的位置精度**，已撤回。v4 给出的是**两条直线的解析交点**：0→1 条在 `λ* = 6.40/(7.625−1.875) = 1.11304`。

**但这里只剩一个交点了。** 旧口径下 1→2 条在 λ*=6.40，那是因为旧 `dup` 混着变义分量、制造出了假的第二交点；换保义口径后再算一遍，**2 条以上的组合没有一个比单开更好**（26 个多开组合里 25 个被严格支配，剩 1 个与单开同坐标），**没有第二个交点可谈**。所以本版明确撤掉"开到几条"这组数值结论——一份不声称最优阈值的报告，比一份用错口径算出最优阈值的报告更可信。

## 重要的诚实声明

**本项目没有调用真实 LLM。** 原计划接真实模型 API 统计字面漂移，实际执行时未取得 API key，因此改为**可控模拟台**（`src/perturb.py`）。这意味着：

- 好的一面：15 个漂移算子的语义性质是显式断言的，可以逐条审计；真调模型反而拿不到这个"标准答案"。
- 坏的一面：真实模型的漂移**分布**必然与我的算子集不同，**绝对数值不可移植**。

因此结论形式是**"排序与机制"，不是"绝对数值"**。3.750 这个数字换一套漂移分布就会变。

**几个必须自己说出来的方法弱点**：

- **出题人与答题人是同一个人。** 契约、诱饵、规则都出自同一双手，共同盲区无法靠自检消除。这一轮有了实证（站号词表与主集耦合）。隐藏集冻结了、哈希可核，但它仍由我构造，**而且其中 2 条正例已经参与过开发**——扣除后正例 6/6、负例 20/20。
- **总代价是测试集分数。** 我最大化的是自己定义的目标函数，不是线上收益。所以主表只并排列两个分量，标量只用于排序，并用 36 组出现率做二维帕累托校验（off-pareto 0/36）。**这个校验是程序自检，不是验证**——正权重下被严格支配的点不可能赢，所以它只说明排序程序没写错。
- **成对计数 ≠ 执行计数。** 本轮用的是诱饵对碰撞率，不是带顺序的调用流仿真。**键不同也不等于系统拒绝了**：E8/E9 检的是"两次请求生成了不同的键"，没有真的执行拒绝、重放或提交。所以"正确拒绝 63 次"这类说法已全部改掉。
- **"只读层没有收益"是设定推论。** 只读工具 `c_dup=0`，重复执行的算力、延迟、配额全被踢出目标函数，那当然不可能靠减少重复拿正收益。这条不是经验发现。
- **"持久化 ID 零错"是错的。** 加上"同身份真实变义"这一类之后，它吞掉 63/63。身份能分开新意图，但分不开"同身份下语义变了"——那需要参数校验。两条路都要，不是二选一。
- **五项交付问题里有一项在本包里仍不闭合，但在仓库里已闭合**：本包为快照分发，没有 `.git/` 也没有 remote；对应仓库 <https://github.com/Liwwh-sys/Lab-Report> 已公开，`PUSH.md` 留了从建仓到 push 的完整命令序列，供复现时自己推一份。

## 工程建议（三条，都不含阈值）

1. **保义归一化可以全开，但要能逐条审计。** 去噪声字段、别名归一、类型归一、按 schema 裁剪、键序固定——这五类在这一版实验里 `fp` 都是 0。但"0"是在我的诱饵集上测出来的 0，上线前要用自己的诱饵集重测。
2. **不要用槽位投影替代幂等协议，也别指望持久化 ID 单独够用。** 槽位投影只能当**请求指纹**用；`op_id` 能分开新意图，但会吞掉全部 63 次真实变义。**身份与校验两条都要。** 字段契约、类型契约、别名契约必须显式声明，**沉默不是许可**；替代的判据用"每段都有归属"，不要用"残余为空"——后者只证明你删干净了，不证明你删对了。
3. **逐条审计，不要打包成一个旋钮。** 五条规则没有一条是纯收益；32 个子集里没有一条多开规则比单开更好（28 个被严格支配，4 个前沿点里 2 点同坐标）；并且它们还依赖执行顺序（Δ 最大 −2.400）。打包成 α 会把这三件事全部抹平。

## 关于仓库

**公开仓库：<https://github.com/Liwwh-sys/Lab-Report>**

本包（ZIP）是**快照分发**：不含 `.git/`，也没有 remote。这不是遗漏，是刻意的——ZIP 解压到任何地方都不该带着一份可能已经过期的 Git 历史。所以 `refute_log.py` 做了什么改动见下：

- **有 `.git/` 时**：从固定提交 `31961e12` 取 v1 三个模块，用 `git rev-parse` 现算 blob SHA 比对 → 证明"内容等于该提交"（`verified_git`）；
- **没有 `.git/` 时**：读随包快照 `src/_v1_snapshot/`，**手算** blob SHA 比对 → 证明"内容未被改动"（`verified_snapshot`）。这**不证明**它来自那个提交，`data/refutation.json` 的 `v1_source` 字段会把是哪一种写清楚；

> **`v1_source` 是运行时算出来的，入库值会与你的运行结果不同。** 仓库里这一份写的是 `verified_git`（作者环境有真 `.git`）；你把包解压到别处直接跑，同一字段会被重写成 `verified_snapshot`。**这不是校验失败，是来源强度降一档**——15 个用例的结果逐位相同，变的只是"凭什么说它是 v1 代码"这一句。想拿回最强判据，用随包的 `idem-key-drift.bundle` 还原一个真仓库再跑。

- **两者都失败时**：`sys.exit(2)`，打印期望/实际哈希或缺失文件名。**不会再出现"打印两行失败但退出码 0"。**

`PUSH.md` 是从建仓到 push 的完整命令序列，供你自己推一份对照。第三轮的交付五项里其余四项已闭环：`refute_log.py` 不再依赖可变 `HEAD`、图 3 的数据链补上了生成出口、`e3_rho.csv` 自动加归档标注、依赖与环境有了三项对账。
